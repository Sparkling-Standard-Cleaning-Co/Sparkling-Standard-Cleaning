# Weekly execution playbook — start here

This is the front door. It is the only document needed to run a normal week; everything else in
`docs/marketing/` is the reference behind it. **Strategy is sophisticated; execution is simple.**

The whole system in one line:

> **GET ATTENTION → GET CONVERSATION → GET FIRST CLEAN → DELIVER EXCELLENTLY → GET RECURRING →
> GET REVIEW → GET REFERRAL → BUILD NEIGHBORHOOD DENSITY → REPEAT.**

If a task in here takes longer to manage than the value it creates, simplify it or drop it.
Customer service and selling always beat marketing administration.

---

## 1. Your first day (if starting tomorrow)

1. **Morning:** check today's jobs and inquiries. Reply to every inquiry first (calls, texts,
   forms) — same-day replies win bookings.
2. **During each clean:** deliver the standard, do the final walkthrough, capture the proof set
   (§4), and present the recurring option (§6).
3. **After each clean:** send the thank-you/check-in, note the next action, ask for the review if
   the link is live (§6).
4. **If it is a door day:** pick the next route from the workbook (§3), knock 50–75 doors, record
   every door, and act on every lead before the day ends.
5. **Evening (10 minutes):** update the tracking file, set tomorrow's first three actions.

No new tools are required. The systems already exist; this playbook just tells you the order.

## 2. Daily rhythm

### Before work

- [ ] Check inquiries (owner inbox + calls/texts) — reply to everything outstanding.
- [ ] Confirm today's job(s): address, time, scope, access notes, permission status.
- [ ] If it is a door day: open the workbook, pick the route, print/cue the route sheet, grab the
      pieces (door hanger / QR estimate card / leave-behind).
- [ ] Charge the phone; clear storage for capture.

### During a cleaning

- [ ] Walkthrough first: confirm scope and anything the customer flags.
- [ ] Clean to the detail standard — corners, fixtures, edges. Never rush it.
- [ ] Capture the proof set (§4) at natural points, not as a separate session.
- [ ] Final walkthrough with the customer (or a completion set if they are out).

### After a cleaning

- [ ] Fix anything the customer noticed before leaving (or return to fix it).
- [ ] Payment after completion (the verified policy).
- [ ] Same-day thank-you; day-2 check-in.
- [ ] Present/confirm the recurring option if it is not already decided (§6).
- [ ] Review request after satisfaction (review link is live); referral card after a visibly great result.
- [ ] Log the job, revenue and any next action in the tracker.

### Door-knocking day

See §3. The whole session is: pick route → knock 50–75 → record every door → act on every lead.

## 3. The 50–75 door system

The **66-route / 4,241-stop / Priority A-B system is canonical** — never modify the route engine.
This is only the operating procedure around it.

**Per door session:**

| Step | What you do |
| --- | --- |
| 1. Which route? | Next Priority A route from `canvass-out/Canvassing-Workbook.xlsx` (or the route sheet). Routes with active customers or recent leads go first. |
| 2. Which segment? | Priority A first; within the route, work the listed order (same-street runs are intentional). |
| 3. Today's target | **50–75 doors** (≈2–2.5 hours including travel at the system's ~30 homes/hour planning pace). If time is short, do a full street, not a scattered half-route. |
| 4. Record every door | Door_Knocked, No_Answer, Conversation, Interested, Phone_Captured, Estimate_Requested, Estimate_Sent, Booked, Recurring_Customer, Notes, Follow_Up_Date. |
| 5. Every lead gets a next action | Estimate requested → send same day/next morning. Interested but not now → one follow-up on the recorded date. Contact captured → add to the lead ledger. No lead disappears. |

**Definitions (keep these exact so the numbers mean something):**

- **Door attempted** — you knocked or rang.
- **Conversation** — someone engaged with you (not just "no thanks" through a window).
- **Interested prospect** — they heard the offer and did not decline (even if not ready).
- **Lead** — phone number captured **or** estimate requested.
- **Booked** — the person confirmed a first clean with Hayli.

**What happens immediately after a lead:**

1. Send the estimate link/text while the conversation is fresh (or note "send by tomorrow 9 AM").
2. Log the lead in the tracker with the follow-up date.
3. Add the address to the customer's route/street record when it books (density, §7).

**Do not:** change ten things at once, argue at a door, knock a "no" twice in one day, or knock
after dark/outside reasonable hours. One piece per door; no littering.

**Record after every session:** doors attempted · conversations · leads · booked · recurring
customers · revenue · objections/reasons for no · neighborhood. That is the whole scoreboard.

## 4. One clean → many assets

One real cleaning should create raw material for several future posts. Capture during the job; no
separate content days.

| Phase | Capture |
| --- | --- |
| **Before** | 1–2 establishing images/clips (wide context of the area being cleaned) |
| **During** | 2–4 process/detail clips (the satisfying part of the work) |
| **After** | 2–4 transformation/detail images/clips (same angles as before where possible) |
| **Optional** | Founder/customer/environment footage — only with permission |

Rules: permission first (logged same day), privacy scrub (no street numbers, mail, documents,
screens, plates), no staged dirt, no fake before/afters. Full detail: `FIELD-CONTENT-CAPTURE.md`
and `docs/privacy/PHOTO-PRIVACY-SOP.md`.

**Repurpose into:** Instagram, TikTok, Facebook, GBP photo/post, website proof (when genuine
material exists), future educational content. One shoot → several publications.

## 5. Content priority (when time is limited)

1. **Real transformation/proof** — the before/after and detail work.
2. **Useful education derived from real work** — what you actually did, why, how to keep it up.
3. **Founder/personality/trust** — Hayli, the standards, the story (owner-approved facts only).
4. **Local/neighborhood content** — availability, "we clean here," community relevance.
5. **Trends/experiments** — only after 1–4 are covered.

Do not create content because a calendar says to. A post that cannot plausibly lead to an inquiry,
a booking or trust is optional. Kill/keep rules: `CONTENT-ENGINE.md` §7.

**Minimum viable week if life happens:** one video + one GBP/local post + one outreach block + one
review ask.

## 6. The customer habit (never let a customer disappear accidentally)

**LEAD → BOOKED → FIRST CLEAN → FOLLOW-UP → REVIEW → RECURRING → REFERRAL → REACTIVATION**

| Moment | Habit |
| --- | --- |
| Lead | Reply same day; log it; one follow-up per the cadence |
| Booked | Confirm personally; add to the schedule; note access details |
| First clean | Deliver; final walkthrough; payment after completion |
| Follow-up | Day 2 check-in ("how does everything feel?") |
| Review | After satisfaction only — request with the configured review link (live); one reminder after ~3 days, then stop |
| Recurring | Present weekly/biweekly/monthly at the first clean; follow up day 2; confirm the rhythm |
| Referral | Hand a referral card after a visibly great result; log the source. No invented incentives — program terms stay owner-gated (`REFERRAL-PROGRAM.md`) |
| Reactivation | One honest touch at 30/60/90 days dormant (seasonal reason, availability, new proof). Never spam |

**Review-link status:** GBP is **verified** and the exact review link is **captured and live**
(`business.reviews.submissionUrl`). Review requests are unblocked — ask after satisfaction, one
reminder, then stop. Never modify or hand-build the URL (`REVIEW-GROWTH-SYSTEM.md`).

**Recurring is the business.** A first clean that becomes a biweekly customer is worth many times
a one-time job. Every clean ends with the recurring conversation.

## 7. Neighborhood density (the compounding habit)

When a customer appears:

1. Record their location (route/street).
2. Identify nearby opportunities on the same/adjacent streets (the route object already lists them).
3. Prioritize nearby homes on the next door day.
4. Use legitimate local proof ("we clean on this street") where true.
5. Track recurring customers by neighborhood.
6. Look for route efficiency (same-street scheduling, grouped days).

Never modify the canonical route data; density only changes **which route you work next**.

## 9. What gets measured (keep it small)

Update the tracker weekly (Sunday, ~15 minutes — `WEEKLY-SCORECARD.md`):

**Acquisition:** doors · conversations · leads · bookings.
**Customers:** first cleans · recurring customers · reviews · referrals · churn/reactivation.
**Economics:** revenue · recurring revenue · revenue per 1,000 doors · recurring customers per
1,000 doors · acquisition cost where measurable.
**Density:** customers and recurring customers by neighborhood.

Nothing else is required at this stage. Do not build a bigger dashboard before meaningful data
exists.

**The first 500–1,000 doors are a learning phase.** Use the actual results to find the best
neighborhoods, the best opening, real lead/booking rates and a sustainable doors-per-day pace.
The 4,000-door scenarios in `ECONOMIC-MODEL.md` are **planning scenarios — not forecasts**;
replace their assumptions with your actual numbers as they arrive.

## 10. The weekly rhythm

| Day | Focus | Time |
| --- | --- | --- |
| Monday | Inquiries + GBP post + reply to reviews | 20 min |
| Tuesday | Door block (50–75) or jobs; capture proof | 2–3 h |
| Wednesday | Publish 1 core content piece (from captured footage) | 30 min |
| Thursday | Door block or jobs; Facebook/Nextdoor local post | 2–3 h |
| Friday | Publish second content piece; follow up all open leads | 45 min |
| Saturday | Jobs or a second door block; batch-edit if needed | — |
| Sunday | Fill the scorecard; pick next week's route, content and 3 decisions | 20 min |

Two door blocks, two content pieces, one local post, all inquiries answered, all leads followed up
— that is a complete week. Adjust to the job schedule; do not sacrifice service for the rhythm.

## 12. Rules that never bend

1. No fabricated reviews, customers, numbers, photos or claims — ever.
2. Fix satisfaction before asking for a review, referral or the next booking.
3. Customer privacy is absolute (`docs/privacy/PHOTO-PRIVACY-SOP.md`).
4. No discount, promotion or referral reward without owner-approved terms.
5. The route engine is canonical; only work-order priority changes.
6. If marketing administration starts consuming selling/cleaning time, simplify the system.
